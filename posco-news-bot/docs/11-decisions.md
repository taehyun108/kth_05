```python
def build_kakao_payload(articles):
    main = [a for a in articles if should_send_kakao(a)]        # 기존 규칙 (INV-4)

    policy_alerts = [
        a for a in articles
        if a.track == "policy"
        and a.sector_impact == "direct"
        and a.impact == "high"
        and a.policy_stage in ("proposed", "enacted", "amended")
        and not should_send_kakao(a)                            # 중복 제외
    ]
    policy_alerts.sort(key=lambda a: a.prescore, reverse=True)
    return main, policy_alerts[:1]                              # ★하루 1건 상한★
```

#### P0-5. 로컬 LLM(L1) 한국어 요약 품질 실측
- **문제:** Ollama 8B급 모델의 한국어 뉴스 요약 품질은 모델별 편차가 크고, 사전에 문서로 확정할 수 없다. **원문에 없는 내용을 지어내면 아카이브 신뢰도가 무너진다.**

- **폴백 순서:** L1 품질 미달 시 → **추출 요약(L0)을 기본값으로 유지**하고 Tier A만 L2(Claude Code)로 처리. 억지로 생성형 요약을 쓰지 않는다

#### P0-6. 사외 → 사내 배포 리스트 수신 허용 확인 *(v1.4 — 사내 확인 결과 문제없음)*

> ✅ **해소.** 사내 배포 리스트 수신에 문제가 없다는 확인을 받았다. §4.11.6 ⑤ 단계적 검증(1주 본인 → 2주 팀원 → 3주 리스트)은 **스팸 학습 방지 목적으로 그대로 권장**하되, 차단 리스크는 낮은 것으로 재평가한다. 아래 원문은 참고용으로 남긴다.


- **해결된 부분:** 발송 한도는 **배포 리스트 주소 1개로 보내면 완전히 해소**된다. 발신자 기준 수신자 1명이므로 개인 Gmail 500통/일, SMTP 100명/메시지 제약에 전혀 걸리지 않는다 (§4.11.6)
- **남은 문제:** 병목이 **수신 측**으로 옮겨갔다. 사내 배포 리스트는 통상 외부 발신자를 차단한다
- **IT에 확인할 것:**
  - [ ] 배포 리스트가 **외부 발신자 메일을 수신**하도록 설정돼 있는가
  - [ ] 아니라면 발신 주소를 **그룹 허용 목록에 등록** 가능한가
  - [ ] 메일 보안 게이트웨이의 **화이트리스트 등록** 절차
  - [ ] **사내 계정 발신**(SMTP 릴레이/Exchange)이 가능한가 ← 가능하면 이게 최선
  - [ ] 외부 계정에서 사내 다수에게 정기 발송하는 것이 정보보호 정책상 허용되는가
- **검증 절차:** 1주차 본인 사내 주소 → 2주차 팀원 2~3명 → 3주차 배포 리스트 (§4.11.6 ⑤). **처음부터 배포 리스트로 쏘면 스팸 신고 한 번에 발신 계정이 통째로 차단될 수 있다**
- **폴백:** 막히면 **텔레그램 `#브리핑` 채널**로 동일 내용 발송. 포맷만 바꾸면 되므로 구현 비용 거의 0

#### ✅ P0-8. 카카오톡 자동화 — **v2.1 확정: Plan B(오픈채팅 API)**

>
> | 항목 | 결과 |
> |---|---|
> | 카톡 자동 발송 (B2) | ✅ 해소 |
> | 사용자 개입 없음 (E3) | ✅ 해소 |

>
> **새로 생긴 부담:** 사람의 최종 확인이 사라지므로 **§4.7.5 안전장치 5종**과 **§4.7.6 오픈채팅방 운영 정책**이 함께 구현되어야 한다. 안전장치 없는 자동 발송은 Plan D보다 위험하다.

## 9. 제약사항 & 리스크

### 9.1 카카오톡 — 최대 제약 ⚠️

확인된 사실:
- 카카오톡 메시지 API(`friends/message`)는 **친구 개인**에게만 발송 가능, **기존 그룹 채팅방 발송 불가**
- 카카오톡 오픈채팅 API는 **API로 생성·관리한 오픈채팅방**에 한해 메시지 전송 제공 (사용 신청 + 도메인 ID 발급 필요)
- 카카오 공식 오픈채팅봇은 환영/자동응답/알림 수준의 기초 기능만 지원
- 알림 리스너·카톡 DB 접근 방식의 비공식 봇은 **이용약관 위반**으로 계정 정지 가능

→ v1은 Plan D(텔레그램 자동 + 카톡 반자동 복사). Plan B는 팀 합의 시 v2.

### 9.2 저작권 · 데이터 이용

| 대상 | 처리 |
|---|---|
| 언론사 기사 | 요약 + 링크만 공개. 본문은 비공개 캐시 90일 |
| 정부 보도자료 (공공누리) | 전문 인용 가능, 출처 표기 |
| 관보·Federal Register·EUR-Lex | 공문서, 인용 가능 |
| **유료 DB (BNEF, Benchmark, SNE 유료분)** | **본문 크롤링 금지.** 공개 요약·헤드라인만. 계약 위반 소지 |
| 이미지·차트 | 사용 금지 (텍스트만) |
