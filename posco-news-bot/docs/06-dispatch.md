### F-10. 발송 라우팅 — 지정 톡방 선별 송부 (v1.2 신규)

> **요구사항:** 통상·규제 기사는 팀 전체 단체방이 아니라 **내가 지정한 톡방에만** 보낸다.

#### 4.10.1 설계 원칙

v1.1까지 발송 규칙은 `should_send_kakao()` 함수 하나에 하드코딩돼 있었다. 톡방이 둘 이상이 되는 순간 이 구조는 무너진다.
→ **발송 대상(방)과 발송 조건을 설정 파일로 분리**한다. 코드 수정 없이 방을 추가·변경할 수 있어야 한다.

#### 4.10.2 `pipeline/dispatch_routes.yaml`

```yaml
version: 1
routes:
  # ── 카카오톡 단체방 (유일한 카톡 라우트 · v1.3) ──
  - id: kakao-team
    channel: kakao
    label: "대외협력팀 단체방"
    enabled: true
    filter:                              # ★트랙 무관 — 포스코 언급 여부만 본다★
      any_of:
        - { posco_relevance: primary }
        - { posco_relevance: mention, impact: [high, mid] }
    room_id_env: KAKAO_OPENLINK_ID       # ★Plan B — API로 생성한 오픈채팅방★
    format: kakao_card_pair              # §4.7.3 — 링크카드 + 요약 2메시지
    daily_limit: 8                       # 카드형은 기사당 2메시지 → 물량 상한 필수
    burst_limit: 3                       # 긴급 푸시 시간당 상한
    overflow: drop                       # ★초과분 미발송 — 목록형 축약 금지 (INV-10)★
    quiet_hours: ["22:00", "07:00"]
    shadow_to_env: TG_CHAT_OPS           # ★발송 사본을 항상 운영 채널로★
    strict_format: true                  # ★§4.7.3 고정 포맷 검증 필수 (INV-10)★
    guards:                              # §4.7.5 이상 감지
      max_volume_ratio: 3.0              # 평소 대비 3배 초과 시 보류
      hold_on_crisis: true               # ★crisis 논조는 자동 발송하지 않는다★
      require_relevance: true            # posco_relevance 판정 실패 건 제외
      summary_len: [50, 600]

  # ── 텔레그램 ──
  - id: tg-posco
    channel: telegram
    chat_id_env: TG_CHAT_POSCO
    filter: { any_of: [ { posco_relevance: primary }, { posco_relevance: mention } ] }
  - id: tg-industry
    channel: telegram
    chat_id_env: TG_CHAT_INDUSTRY
    filter: { track: [battery] }
  - id: tg-policy
    channel: telegram
    chat_id_env: TG_CHAT_POLICY
    filter: { track: [policy, trade], sector_impact: direct }

  # ── 메일 (§F-11) — T1~T4 전부 담는 유일한 채널 ──
  - id: mail-daily
    channel: mail
    to_env: MAIL_TO_GROUP                # 사내 배포 리스트 주소 1개 (§F-11.6)
    schedule: "07:00"
    format: daily_two_part
    parts:
      - id: A                            # 포스코 언론 클리핑 (언론사별 정렬)
        filter: { posco_relevance: [primary, mention] }
        group_by: outlet
      - id: B                            # 정책·통상 브리핑 (포스코 미언급분)
        filter:
          all_of:
            - { track: [policy, trade] }
            - { posco_relevance: none }
            - { impact: [high, mid] }
        group_by: track_category
```

#### 4.10.3 발송 관리 패널 (v2.1 역할 재정의)

> **Plan B 채택으로 이 패널은 "매일 쓰는 도구"에서 "가끔 쓰는 관리 도구"가 됐다.** 상시 발송은 자동이고, 패널은 예외 상황을 다룬다.

| 용도 | 시점 |
|---|---|
| **킬 스위치 토글** | 사고 시 즉시 발송 중단 |
| **보류 건 검토·승인** | 이상 감지에 걸린 건(특히 `crisis`)을 사람이 보고 발송/폐기 결정 |
| **수동 발송** | 자동에서 빠졌지만 공유해야 할 기사 |
| **재발송** | API 실패로 누락된 건 |
| **발송 이력 조회** | 무엇이 언제 나갔는지 |
| 복사 발송 (폴백) | 카카오 API 장애 시 아래 흐름으로 수동 전송 |

**폴백 복사 흐름 (API 장애 시에만)**

카드형은 기사당 **링크 → 요약** 순으로 **두 번 붙여넣어야** 한다. 클립보드는 한 번에 하나뿐이므로, 단순 "복사" 버튼으로는 운영이 불가능하다.
→ 웹에 **발송 모드 패널**을 둔다.

```
┌─ 📤 카톡 발송 모드 · 8/26(수) · 6건 ─────────────┐
│                                                   │
│  진행  ●●●○○○   3/6                              │
│                                                   │
│  ④ [뉴스토마토] 미·캐나다 '관세전쟁' 불똥?…       │
│                                                   │
│   STEP 1  링크                                    │
│   ┌───────────────────────────────────────────┐  │
│   │ https://www.newstomato.com/...            │  │
│   └───────────────────────────────────────────┘  │
│                          [📋 복사하고 다음 →]     │
│                                                   │
│   STEP 2  요약  (STEP 1 복사 후 활성화)           │
│   ┌───────────────────────────────────────────┐  │
│   │ [뉴스토마토] 캐나다에 현지 생산 기반을...  │  │
│   └───────────────────────────────────────────┘  │
│                          [📋 복사하고 다음 →]     │
│                                                   │
│  [◀ 이전]                    [건너뛰기]  [완료]   │
└───────────────────────────────────────────────────┘
```

**동작**
- `[복사하고 다음]` → 클립보드 복사 + 자동으로 다음 STEP/기사로 이동 → **버튼만 반복 탭하면 되는 흐름**
- 각 복사 시각을 `dispatch_log`에 기록 → 재진입 시 `이미 09:12에 발송함` 경고
- `[건너뛰기]` — 담당자 판단으로 특정 기사 제외 (사유 선택 시 다음날 필터 개선에 반영)
- 모바일에서도 동작해야 한다. 출근길에 폰으로 붙여넣는 경우가 많다
- 요약 텍스트는 **편집 가능**하게 둔다. 자동 생성 문장을 사람이 다듬고 보내는 것이 현실적이다

> Plan B(오픈채팅 API)로 전환하면 이 패널은 그대로 두되 `[전체 자동 발송]` 버튼이 추가된다. `filter`·`format` 정의는 재사용된다.

### F-07. 카카오톡 발송

> **⚠️ §9.1 제약사항을 먼저 읽을 것.** 기존 카카오톡 단체방으로 API 자동 발송하는 공식 경로는 없다.

#### 4.7.1 발송 게이트 (INV-4)

```python
def should_send_kakao(a) -> bool:
    if a.posco_relevance == "primary":
        return True
    if a.posco_relevance == "mention" and a.impact in ("high", "mid"):
        return True
    return False          # none → 웹/텔레그램만
```

- 트랙과 무관하다. T3 정책 기사여도 포스코가 유의미하게 언급되면 발송된다.
- 메시지에는 **요약·링크만**. SWOT·시사점·정책건의 미포함.
- **Fail-closed:** 게이트 판정에 필요한 필드가 없거나 오류면 **발송하지 않는다.** (§12 검증 5회차)

#### 4.7.2 발송 경로 옵션

| Plan | 방식 | 합법성 | 판정 |
|---|---|---|---|
| **A** | 카카오톡 채널 + 친구톡/알림톡 (비즈메시지) | ✅ 공식 | 유료·템플릿 심사·개인 수신 (단체방 아님) |
| **B** | 카카오톡 오픈채팅 API | ✅ 공식 | **API로 생성한** 오픈채팅방 한정 → 팀 이주 필요 |
| **C** | PC 카톡 GUI 자동화 | ❌ 약관 위반 소지 | 계정 정지 리스크 · 사내 도입 비권장 |
| **D** | 봇이 텍스트 생성 → 담당자 1클릭 복사 후 붙여넣기 | ✅ | **v2.1에서 보조로 강등** — 수동 발송·재발송 도구로만 유지 |

> ✅ **v2.1 확정: Plan B(오픈채팅 API).** 팀의 신규 오픈채팅방 이주가 가능하다는 확인을 받았다.
> API로 생성·관리하는 오픈채팅방에 한해 서비스에서 API로 메시지를 보낼 수 있으므로, **수집→분석→발송 전 구간이 사람 개입 없이 자동화**된다(요구사항 E3 충족).

#### 4.7.3 메시지 포맷 — `kakao_card_pair` 🔒 **고정 명세 (FROZEN)**

> 🔒 **이 절은 고정 명세다.** 아래 형태 외의 어떤 변형도 발송하지 않는다.
> 헤더 메시지, 목록형 축약, 논조 배지, 긴급 표시, 요일별 변형, 건수 안내 — **전부 금지**한다.
> 기사 1건은 **언제나 정확히 메시지 2개**이며, 그 구조는 아래 하나뿐이다.

**구조 — 기사 1건 = 메시지 2개 (순서 고정)**

```
─── 메시지 1 : 링크 카드 ───────────────────
┌──────────────────────────────────────┐
│  [썸네일 이미지]                       │  ← ① thumbnail
│                                       │
│  미·캐나다 '관세전쟁' 불똥?…산업계     │  ← ② title  (굵게)
│  '촉각'                                │
│                                       │
│  미·캐나다 북미 생산거점 관세 부담      │  ← ③ description (연한 회색)
│  가능성                                │
│                                       │
│  www.newstomato.com                   │  ← ④ domain (링크)
└──────────────────────────────────────┘

─── 메시지 2 : 요약 본문 ───────────────────
[뉴스토마토] 캐나다에 현지 생산 기반을 구축 중인 배터리 업계는 양국의
통상 갈등 확대 가능성을 주시하고 있습니다. 현재 LG에너지솔루션(373220)은
캐나다 온타리오주에 배터리 생산법인 '넥스트스타 에너지'를 운영 중이고,
포스코퓨처엠은 퀘백주에 GM과 함께 양극재 합작사 '얼티엄캠'을 설립하고
연산 3만톤 규모의 생산기지를 짓고 있습니다.
```

##### 메시지 1 — 카드 4요소 (전부 우리가 명시 지정)

| # | 요소 | 값 | 규칙 |
|---|---|---|---|
| ① | `thumbnail` | 기사 대표 이미지 URL | 원문 OG 이미지 **URL 참조**(재호스팅 금지). 없으면 **기본 썸네일** 사용 — 카드 형태는 절대 무너뜨리지 않는다 |
| ② | `title` | **기사 제목 원문 그대로** | 수정·요약·말줄임 금지. 매체가 붙인 따옴표·물음표 유지 |
| ③ | `description` | **기사 부제** | 부제가 없으면 `summary` 첫 문장을 40자 내로 절삭해 사용 (빈칸으로 두지 않는다) |
| ④ | `link` | **언론사 원문 URL** | 도메인이 카드 하단에 표시된다. 네이버 중계 링크보다 원문 우선, 단축 URL 금지 |

> 🔒 **OG 자동 미리보기에 의존하지 않는다.** URL만 던져 클라이언트가 렌더하게 두면 **매체마다 썸네일 유무·설명 길이가 제각각**이 되어 "형태 고정"이 깨진다. 네 요소를 전부 지정해 **어떤 매체의 기사든 동일한 카드**가 나오게 한다.

##### 메시지 2 — 요약 본문

| 항목 | 규칙 |
|---|---|
| **머리말** | 반드시 `[매체명] ` 으로 시작. 대괄호 안은 언론사명만, 뒤에 공백 1칸 |
| **본문** | 머리말에 이어 **한 문단**으로 연결. 의도적 줄바꿈 없음 (말풍선 자동 줄바꿈만) |
| 문체 | **존댓말 평서문** (`~습니다`, `~하고 있습니다`). 개조식·명사형 종결 금지 |
| 분량 | **3~5문장, 150~350자** |
| 구성 | ① 사안의 배경·현황 → ② 관련 기업의 구체적 상황 → ③ (있으면) 관전 포인트 |
| **포스코 언급 필수** | `mention` 기사여도 포스코 계열사가 등장하는 문장을 반드시 포함 |
| 고유명사 | 상장사는 **종목코드 병기** — `LG에너지솔루션(373220)`. 법인·JV·지역명은 원문 표기 유지 |
| 수치 | 기사의 구체 수치를 살린다 — `연산 3만톤`, `25% 관세` |
| **절대 금지** | 이모지 · 불릿(`•` `└` `·`) · 해시태그 · 마크다운 · 논조 배지 · 중요도 표시 · URL |
| 금지 | SWOT · 시사점 · 대응논리 (INV-3) |
| 인용 | 원문 문장을 그대로 옮기지 않는다. 자체 문장으로 재작성 (§9.2) |

##### 🔒 폐기된 요소 (v2.2 — 발송 금지 목록)

| 폐기 | 사유 |
|---|---|
| ❌ 헤더 메시지 (`📰 포스코 관련 뉴스 8/26(수) · 6건`) | 고정 형태에 없다 |
| ❌ 목록형 축약 메시지 (`overflow: list_tail`) | 다른 형태가 섞인다. **상한 초과분은 발송하지 않고 웹·메일로만 전달** |
| ❌ 긴급 푸시 전용 포맷 | `crisis`도 승인 후 **동일 포맷**으로 발송 |
| ❌ 논조·중요도 배지 | 내부 판정값을 단체방에 노출하지 않는다 |
| ❌ 일일 요약·마무리 멘트 | 고정 형태에 없다 |

##### 발송 전 포맷 검증기 (Formatter Contract)

형태 고정은 **문서가 아니라 코드로 강제**한다. 아래를 통과하지 못한 건은 **발송하지 않는다**(fail-closed).

```python
BANNED = re.compile(r'[\U0001F300-\U0001FAFF\u2600-\u27BF]|^[•·\-└*]|#\w|\*\*|https?://')

def validate_kakao(card: dict, body: str) -> list[str]:
    e = []
    # 메시지 1 — 카드 4요소가 모두 있어야 한다
    for k in ('thumbnail', 'title', 'description', 'link'):
        if not card.get(k): e.append(f'card.{k} 누락')
    if card.get('link','').startswith(('http://bit.ly','https://bit.ly')): e.append('단축 URL')

    # 메시지 2 — 머리말·문체·분량·금지문자
    if not re.match(r'^\[[^\]]{2,12}\] \S', body):     e.append('[매체명] 머리말 형식 위반')
    if '\n' in body:                                    e.append('의도적 줄바꿈')
    if not (150 <= len(body) <= 350):                   e.append(f'분량 이탈 {len(body)}자')
    if BANNED.search(body):                             e.append('금지 문자(이모지/불릿/해시태그/URL)')
    if not body.rstrip().endswith('다.'):                e.append('존댓말 평서문 종결 아님')
    if not any(k in body for k in POSCO_ENTITIES):      e.append('포스코 언급 없음')
    return e
```

- 검증 실패 건은 **해당 기사만 제외**하고 나머지는 정상 발송한다 (전체 중단 금지)
- 실패 내역은 실행 리포트와 운영 채널로 통지 → `summarizer` 프롬프트 개선에 반영
- 이 검증기는 **회귀 테스트로 고정**한다. 예시 카드(뉴스토마토 건)를 골든 샘플로 저장해 CI에서 대조

##### 물량 상한

```yaml
daily_limit: 8          # 기사 8건 = 메시지 16개
                        # 초과분은 발송하지 않는다 (웹·메일에 있음)
```

선정 순서: `impact` → `posco_relevance=primary` 우선 → `prescore`

#### 4.7.4 카드 렌더 실패 시

| 상황 | 대응 |
|---|---|
| 썸네일 URL이 죽어 있음 | **기본 썸네일로 대체**하고 카드는 그대로 발송 (형태 유지) |
| 기사 부제 없음 | `summary` 첫 문장 40자 절삭 (빈칸 금지) |
| 템플릿 전송 API 실패 | **재시도 2회** → 계속 실패하면 해당 건 **미발송** + 운영 알림. 다른 형태로 대체 발송하지 않는다 |
| 오픈채팅 API 전면 장애 | 발송 중단 + 운영 알림 → §4.10.3 관리 패널에서 수동 복사 발송 |

> 🔒 **"형태가 깨질 바에는 보내지 않는다"** 가 원칙이다. 다른 모양으로 대체 발송하면 고정 명세가 무의미해진다.

#### 4.7.5 오발송 안전장치 (v2.1 신규) ⚠️ **자동화의 대가**

> **Plan D에는 숨은 안전장치가 있었다 — 사람이 마지막에 눈으로 봤다.** 담당자가 복사하다가 "이건 아닌데" 싶으면 건너뛸 수 있었다. Plan B로 가면 그 관문이 사라진다. **잘못 나간 메시지는 되돌릴 수 없다.**
> 아래 5종은 그 관문을 대체하는 보상 통제다.

**① 킬 스위치**

```yaml
# dispatch_routes.yaml
- id: kakao-team
  enabled: true        # ★false 한 줄로 즉시 발송 중단★
```
- 코드 배포 없이 끌 수 있어야 한다. 사고는 배포를 기다려주지 않는다
- 웹 관리 화면(`/dispatch/`, L2)에서도 토글 가능하게 한다

**② 발송 전 이상 감지 (Anomaly Guard)**

발송 직전에 아래를 검사하고, 하나라도 걸리면 **발송을 보류하고 담당자에게 알린다**.

| 조건 | 임계 | 조치 |
|---|---|---|
| 발송 건수 급증 | 평소 대비 3배 초과 | 보류 → 수동 확인 |
| 발송 건수 0 | 평일 0건 | 보류 → 파이프라인 이상 의심 |
| `tone=crisis` 포함 | 1건 이상 | **보류 → 반드시 사람이 먼저 본다** |
| `posco_relevance` 판정 실패 | 1건 이상 | 해당 건만 제외 (fail-closed, INV-4) |
| 요약 길이 이상 | 50자 미만 / 600자 초과 | 해당 건 제외 |
| 동일 URL 중복 | `dispatch_log` 히트 | 해당 건 제외 |

> **`crisis` 건을 자동 발송하지 않는 것이 특히 중요하다.** 안전사고·법적분쟁 기사는 홍보실 방침이 먼저 정해져야 하는 사안이다. 봇이 먼저 단체방에 뿌리면 곤란해진다.

**③ 섀도 운영 (초기 2주)**

```
1주차: 발송 대상을 ★담당자 개인 톡방/텔레그램으로만★ 보낸다
       → 실제 단체방에는 안 나감. 매일 눈으로 검증
2주차: 단체방 발송 + 담당자에게 동일 사본 전송
3주차~: 정상 운영 (사본은 계속 유지 — 무엇이 나갔는지 항상 안다)
```

**④ 발송 로그와 사후 확인**

- `dispatch_log`에 발송 시각·기사 id·본문 전문 기록
- 매 발송 후 실행 리포트에 `카카오 8건 발송` + 목록을 담아 텔레그램 `#운영-알림`으로 통지
- 오발송 시 **정정 메시지 템플릿**을 미리 준비해 둔다 (카톡은 삭제해도 이미 읽힌다)

**⑤ 발송량 상한**

```yaml
daily_limit: 8              # 카드+요약 = 최대 16메시지
burst_limit: 3              # 긴급 푸시는 시간당 3건까지
quiet_hours: ["22:00","07:00"]   # 야간 발송 금지, 다음 발송으로 이월
```

#### 4.7.6 오픈채팅방 운영 정책 (v2.1 신규)

오픈채팅은 일반 단체방과 성격이 다르다. **링크만 알면 외부인이 들어올 수 있다.** 사내 업무 정보가 오가는 방이므로 아래를 반드시 설정한다.

| 항목 | 설정 | 이유 |
|---|---|---|
| **입장 코드** | **필수 설정** | 링크 유출만으로 입장되는 것을 막는다 |
| **검색 노출** | **차단** | 오픈채팅 검색에 잡히지 않게 |
| 관리자 | 담당자 + 부관리자 1명 | 단독 관리는 부재 시 위험 |
| 정원 | 팀 인원 + 여유 소수 | 과다 설정 지양 |
| 프로필 | 실명 닉네임 권장 | 오픈채팅 기본은 익명 — 업무방에 부적합 |
| 정기 점검 | 월 1회 참여자 명단 확인 | 퇴사·이동자 정리 |

**이주 체크리스트**

- [ ] 카카오 오픈채팅 API 사용 신청 및 도메인 ID 발급 (심사 기간 있음 — **최우선**)
- [ ] API로 오픈채팅방 생성 → 입장 코드·검색 차단 설정
- [ ] 팀원 이주 안내 (기존 방에 링크 공지, 1~2주 병행 운영)
- [ ] 기존 단체방은 **아카이브 목적으로 유지** (오픈채팅은 이전 대화 이관 불가)
- [ ] 사내 보안정책상 오픈채팅 업무 사용 가능 여부 확인
- [ ] 봇 계정을 방 관리자로 지정

> ⚠️ **기존 단체방의 대화 히스토리는 옮겨지지 않는다.** 과거 공유 기사를 참조해야 한다면 기존 방을 지우지 말고 남겨 둔다.
