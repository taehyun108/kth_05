#### 4.1.3-A 법령 트랙 (`pol-law`) 상세 — v2.0 신규

> **요구사항 C4:** *"[법령] 행정예고 시 당사 영향 및 SWOT 분석"*
> 법령은 뉴스와 성격이 다르다. **기사가 나기 전에 관보·예고 단계에서 잡아야** 대응 시간이 생긴다. 시행된 뒤 기사로 아는 것은 이미 늦다.

**수집 소스 (뉴스보다 원문이 우선)**

| 소스 | 방식 | 잡히는 것 | 안정성 |
|---|---|---|---|
| **국가법령정보센터 Open API** (법제처) | 무료 API (인증키 신청 필요) | 법령 제·개정, 시행일, 조문 | 높음 |
| **입법예고** (국회·정부) | 목록 페이지 | 법률안 예고 | 중간 |
| **행정예고** (부처 공고) | 관보·부처 게시판 | 고시·훈령·예규 개정 | 중간 |
| 대한민국 전자관보 | 공고 | 공포 확정 | 높음 |
| 규제정보포털 | 규제영향분석서 | **규제 신설 시 산업 영향 분석 원문** | 중간 |
| 뉴스 | 기존 파이프라인 | 해설·업계 반응 | — |

> ⚠️ 국가법령정보센터 API는 **무료지만 인증키 신청이 필요**하다. §11.6의 "API 키 불요" 원칙은 **LLM에 한한 것**이며, 공공데이터 API는 예외로 둔다. 신청이 지연되면 목록 페이지 파싱으로 대체한다.

**법령 엔티티 (`private/data/laws.json`)**

정책·분쟁과 동일하게 **법령 자체를 엔티티로 관리**하고, 예고·공포·시행을 상태 변화로 기록한다.

```jsonc
{
  "laws": [
    {
      "law_id": "kr-battery-special-act",
      "name": "이차전지산업 경쟁력 강화 및 지원에 관한 특별법",
      "ministry": "산업통상자원부",
      "type": "법률",                      // 법률 | 시행령 | 시행규칙 | 고시 | 훈령
      "current_stage": "notice",           // draft|notice(예고)|passed|promulgated|effective|amended
      "notice_period": { "from": "2026-08-20", "to": "2026-09-29" },
      "effective_date": null,
      "affects_futurem": true,
      "affected_articles": ["제12조 세제지원", "제18조 인력양성"],
      "obligation_type": ["지원", "신고의무"],   // 지원 | 규제 | 신고의무 | 처벌
      "timeline": [
        { "date": "2026-08-20", "stage": "notice", "source": "행정예고 제2026-000호",
          "article_ids": ["..."], "note": "40일 예고" }
      ],
      "our_position": "제12조 적용대상에 음극재 포함 필요",
      "comment_deadline": "2026-09-29",     // ★의견제출 마감 — 알림 트리거★
      "linked_issue_id": "2026-W35-battery-act"
    }
  ]
}
```

**행정예고 대응 워크플로 (요구사항 C4의 핵심)**

```
법령 예고 감지 (law-watch, 매 2시간)
  ↓
① affects_futurem 판정 — 적용대상·품목·의무 사전 매칭 (L0 규칙)
  ↓ true
② 조문 단위 요약 + 당사 영향 분석 (L2)
   "제12조 세제지원 대상에 양극재는 포함, 음극재는 미포함"
  ↓
③ 퓨처엠 기준 SWOT + 의견제출 초안 (L2)
   → response.policy_ask = "제12조 적용대상에 음극재 추가 요청"
  ↓
④ ★의견제출 마감 D-14 / D-7 / D-3 알림★
   예고기간을 놓치면 대응 기회 자체가 사라진다
  ↓
⑤ 웹 /policy/ 법령 탭 + 메일 Part B + (포스코 언급 시) 카톡
```

> 💡 **`comment_deadline` 알림이 이 트랙에서 가장 실용적인 기능이다.** 행정예고는 통상 20~40일인데, 그 기간을 놓치면 의견을 낼 수 없다. 대외협력 업무에서 이 알림 하나가 시스템 전체 값어치를 할 수 있다.

#### 4.1.5 공통 네거티브 필터

> 💡 **정책·통상 트랙의 핵심 가치는 "예고 단계 포착"이다.** 시행 후 기사로 아는 것과, 입법예고·Federal Register 공고 단계에서 아는 것은 대응 시간이 수 주 차이 난다. 이것이 T3를 뉴스만으로 채우지 않는 이유다.


```yaml
negative_keywords: [테마주, 리딩방, 상한가, 급등주, 채용공고, 주가 전망, 목표주가]
negative_outlets: [<광고성 매체 리스트 — 운영하며 축적>]
negative_patterns:
  - "^\\[부고\\]"
  - "^\\[인사\\]"          # 단, T1은 인사 기사 유지 (그룹 인사는 대외협력 관심사)
  - "^\\[포토\\]"
  - "증권가 소식"
```

**검색 API 방식과의 근본 차이 — 질의가 아니라 피드다.**
검색 API는 "키워드로 물어보는" 방식이라 등록 매체 개념이 없었지만, RSS는 **등록한 매체만 본다.**
따라서 ⓐ 피드 전체를 받아 `must` 키워드(+`posco_entities`)로 거르고, ⓑ 커버리지 누락을 §4.1.7 로 감시한다.

**키워드 매칭은 공백을 무시한다 (`s1_collect._squash`).**
한국어 기사는 같은 개념을 띄어쓰기만 바꿔 쓴다 — `음극 소재`/`음극소재`, `양극 활물질`/`양극활물질`, `삼성 SDI`/`삼성SDI`.
사전에 모든 변형을 넣는 대신 양쪽에서 공백을 지우고 비교한다. 원문 그대로도 함께 본다.
부작용으로 단어 경계를 넘는 오탐이 가능하지만(`음극 재활용`→`음극재활용` ⊃ `음극재`), 이 단계는 **최종 판정이 아니라 수집 후보 선별**이고 하류 prescore·dedup 이 더 거른다.

**정규화 계층 (`pipeline/stages/rss.py`) — 매체별 편차를 여기서 흡수한다.**

| 편차 | 흡수 방법 |
|---|---|
| 포맷 | RSS 2.0 `<item>` → 없으면 Atom `<entry>` 폴백 |
| 날짜 | RFC822(오프셋·GMT) → ISO8601(Z·오프셋) → 공백구분 naive(KST 가정) → 실패 시 `null` |
| 설명 | `description` → `content:encoded` → `summary` → `atom:content` → `""` |
| 제목·본문 | CDATA · HTML 태그 · HTML 엔티티 제거 |
| 링크 | `<link>` 텍스트 → Atom `<link href=...>` |
| 분류 | `<category>` 다중 → Atom `term=` |

> ⚠️ **탈락한 소스** — 네이버 검색 API는 2026-06 NAVER API HUB 이관, 2026-07-31 개발자센터 신규 신청 종료로 네이버클라우드 결제수단이 필요해 사용하지 않는다(어댑터만 비활성 보존). 빅카인즈 Open API는 2025년 유료 전환 + **기사 재배포 금지 조항**으로 후보에서 제외한다.
> ⚠️ 네이버 뉴스 페이지 직접 스크래핑은 약관/robots 이슈로 하지 않는다. 원문 URL은 언론사 RSS에서 그대로 오므로 `originallink`/중계링크 처리 로직 자체가 필요 없다.

#### 4.1.7 응답 검증 — **200은 성공을 뜻하지 않는다**

실호출에서 두 번 확인된 사실이다. 전자신문 소재 피드는 200·정상 XML을 주면서 **68일째 갱신이 멈춰** 있었고,
이데일리 `/rss/` 는 200을 주면서 **ASP.NET 오류 폴백 페이지**(`?aspxerrorpath=/rss/`)였다.
그래서 파싱 전에 네 가지를 본다 (`rss.validate_response`). 하나라도 실패하면 **그 피드는 수집 실패**로 기록한다.

| # | 검사 | 잡는 것 | 리포트 문구 |
|---|---|---|---|
| ① | 최종 URL에 오류 표식(`aspxerrorpath`·`/error`·`404`…) | 오류 페이지 폴백 | `오류 페이지로 리다이렉트 (…)` |
| ① | 최종 URL의 호스트·경로가 요청과 다름 | 엉뚱한 곳으로 유도 | `다른 주소로 리다이렉트 (… → …)` |
| ② | `Content-Type` 이 xml 계열(`xml`/`rss`/`atom`) | HTML 응답 | `200 이지만 XML 아님 (Content-Type: text/html)` |
| ③ | 루트 엘리먼트가 `rss`/`feed`/`RDF` | 헤더만 xml인 HTML | `200 이지만 피드 아님 (루트 <html>)` |
| ④ | `item`/`entry` 1건 이상 | 빈 껍데기 피드 | `피드 구조는 맞지만 item/entry 0건` |

`Content-Type` 이 비어 있으면 ②를 건너뛰고 ③④로 판정한다(헤더를 안 주는 서버가 있다).

**등록 규칙 — `verified: false` 는 켜지지 않는다.**
`load_sources()` 가 강제로 `enabled: false` 로 내린다. **예외 없음.**
주소를 추정으로 적어 둔 피드가 켜져 있으면 "수집이 도는 것처럼 보이는데 실제로는 비어 있는" 상태가 된다.
꺼진 피드는 `coverage.pending_feeds` 로 리포트에 `⏸ 확인 대기` 로 계속 노출된다.

#### 4.1.8 카테고리 필터 (2단 구조)

`<category>` 를 채워 주는 피드는 **카테고리로 먼저 줄이고, 그다음 `keywords.yaml` 로 거른다.**
`rss_sources.yaml` 의 피드별 `category_filter` (부분일치 목록). 미설정이면 전부 통과 → 전자신문처럼 카테고리가 없는 피드는 그냥 안 쓰면 된다.

```yaml
  - id: edaily-all
    category_filter: ["산업", "정책", "전자", "경제", "과학", "국제", "기업", "증권"]
```

> **카테고리가 빈 항목은 버리지 않는다.** 매체의 분류 누락 때문에 기사를 잃는 쪽이 더 나쁘다.

#### 4.1.7 커버리지 감시 (RSS 전환에 따른 필수 장치)

RSS는 등록한 매체만 보므로 **누락이 조용히 일어난다.** 실행 리포트(S8)에서만 드러나게 한다.

| 지표 | 산출 | 리포트 표기 | 조치 |
|---|---|---|---|
| 매체별 수집 건수 | `coverage.by_outlet` | `매체별(N개 매체, 상위 10)` | 특정 매체 급감 확인 |
| 피드별 원본 건수 | `coverage.feed_counts` | `이번 실행 0건 피드` | URL·차단 점검 |
| 죽은 피드 의심 | `state/feed_health.json` 의 연속 0건 ≥ 3회 | `⚠️ 죽은 피드 의심` | `rss_sources.yaml` URL 수정 |
| **정체된 피드** | 최신 기사 발행일이 임계 이상 과거 (`coverage.stale_feeds`) — 임계는 피드별 `stale_days`, 기본 14일 | `⚠️ 정체된 피드` | 섹션 폐지 여부 확인 → 대체 피드로 교체 |
| 피드별 최신 기사일 | `coverage.feed_newest` / `feed_age_days` | `피드별 최신 기사:` — **판정과 무관하게 항상 표시** | 추세 관찰(정체는 서서히 온다) |
| RSS 미등록 매체 후보 | 구글로만 잡힌 매체 중 `rss_sources.yaml` 에 없는 것 | `ℹ️ RSS 미등록 매체 후보` | 피드 주소 찾아 등록 |

> **정체된 피드는 죽은 피드와 다른 고장 모드다.** 200 OK, 항목 50건, 파싱 정상 — 그런데 전부 과거 기사인 경우가 실제로 있다(2026-09-01 확인: 전자신문 `06064.xml` 소재 섹션이 68일째 정체). 건수 기반 감시로는 영원히 안 잡히므로 **최신 기사 발행일**을 따로 본다.

산출물: `raw/<run_id>/coverage.json`

### F-02. 정규화 · 중복제거 · 사전 게이트 (Normalizer)

**출력:** `raw/<run_id>/normalized.jsonl`

#### 4.2.1 기사 ID 생성 (v1.0 변경)

```python
# v0.2: f"{date}-{slugify(title)}"  ← 제목 수정 시 id 변경 → 즐겨찾기·이슈 참조 파손
# v1.0:
article_id = f"{date}-{sha1(canonical_url)[:10]}"
# 예: "2026-08-26-a3f9c1d2e8"
```

- 원문 URL이 정본(canonical). 트래킹 파라미터(`utm_*`, `sid`, `ref`) 제거 후 해시
- 같은 기사가 언론사 RSS·구글 양쪽에서 잡혀도 동일 id로 수렴
- `title_slug`는 사람이 읽는 용도로 별도 필드에 보관 (URL 경로에는 `id` 사용)

#### 4.2.2 중복 제거 3단계

| 단계 | 방법 | 처리 |
|---|---|---|
| L1 URL | canonical URL 완전 일치 | 병합 (`sources[]`에 소스 누적) |
| L2 제목 | 정규화 후 유사도 ≥ 0.9 (SimHash / 자카드) | 대표 1건 선정, 나머지 `dedup_of` |
| L3 본문 | 크롤링 후 본문 SimHash ≥ 0.85 (통신사 전재) | 대표 1건 선정 |

**대표 기사 선정 기준:** ① 원 통신사(연합·뉴시스) > ② 매체 티어 상위 > ③ 발행 시각 빠름
**⚠️ 주의:** 대표 기사가 일일 상한에 걸려 탈락하면 `dedup_of` 포인터가 끊긴다 → **대표 기사는 상한 컷에서 면제**한다. (§12 검증 2회차)

#### 4.2.3 사전 스코어 & 일일 상한 (v1.0 신규 — 순서 결함 수정)

> **문제:** v0.2는 "카테고리별 일일 상한 + `impact` 컷"이라고 썼는데, `impact`는 LLM 분석 **후**에 생기는 값이다. 분석 전에 컷하려면 분석 없이 계산 가능한 점수가 필요하다. (§12 검증 2회차)

```python
prescore = (
    outlet_tier_weight        # 티어1 매체 3.0 / 티어2 2.0 / 기타 1.0
  + keyword_weight            # must 키워드 히트 2.0, expand 1.0 (합산, 상한 4.0)
  + posco_string_hit * 3.0    # 포스코 문자열 등장 (강한 가중)
  + recency_weight            # 6시간 이내 1.0
  - duplicate_penalty         # 유사 기사 다수 존재 시 감점
)
```

**2단계 컷 구조**

```
수집 (예: 340건)
  → 네거티브 필터            → 280건
  → dedup L1·L2              → 165건
  → prescore 정렬 후 카테고리별 상한 적용 → 110건   ← [사전 컷]
     · 단, posco_string_hit 기사는 상한 면제
     · 단, 전재 대표 기사는 상한 면제
  → FETCH + ANALYZE (110건)
  → dedup L3 (본문 기준)     → 98건
  → impact=low AND track!=posco 인 기사는 카드 노출은 하되
     '더보기' 접힘 처리                              ← [사후 컷]
```

#### 4.2.4 트랙 판정 및 `posco_relevance` 1차 판정

- `track` — §1.3 경계 판정 규칙 적용 (룰 기반 1차 → S4c에서 LLM 검증)
- `posco_relevance` — 문자열 매칭으로 후보만 추출, 최종 판정은 S4c

### F-03. 본문 크롤링 (Fetcher)

**적용 대상:** T1·T2·T3 **전 기사 동일** (INV-1)
**출력:** `cache/<url_hash>.json` — `{url, fetched_at, title, body, byline, published_at, outlet, lang}`
**저장 위치:** **PRIVATE repo 또는 로컬** (public repo 저장 금지 — INV-5)

- 추출 엔진: `trafilatura`(1순위) → `readability-lxml` → `newspaper3k`
- **robots.txt 준수**, User-Agent 명시, **도메인별 요청 큐 + 간격 ≥ 1.5초**
- 동시성: 전역 8, 도메인별 1
- 실패 시: 검색 API `description` 스니펫으로 degrade → `crawl_status: partial`
- 페이월 감지(본문 <300자 + 로그인 키워드) → `paywall: true`, 제목·링크만
- PDF 리포트: `pdfplumber`로 텍스트 추출 (기관 리포트 대응)
- 영문 기사: 본문 원문 저장, **요약은 한국어로 생성** (`lang: en`, `summary_lang: ko`)
- 캐시 TTL 90일, 만료 시 자동 삭제

> 🔒 **저작권 원칙:** 본문 전문은 **비공개 캐시에만** 저장하고, 웹·카톡·텔레그램에는 **자체 작성 요약문 + 원문 링크**만 게시한다. 원문 인용은 문장당 1개, 짧게. 단, **공공누리 적용 정부 보도자료는 예외**로 전문 인용 가능(출처 표기).
